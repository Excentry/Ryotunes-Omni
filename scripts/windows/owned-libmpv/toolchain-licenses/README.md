# Toolchain notice inputs

Original notice texts in this directory are copied without rewriting from fixed upstream revisions. `../notice-inputs.lock.json` records their URLs and SHA-256 checksums. Source preparation includes this directory in the recipe inside `source-inputs.tar.gz`; packaging verifies the recorded bytes and copies the texts into `licenses/toolchain/`.

For the selected DLL SHA-256 `6a6ac973ecb495b6799b32d221fdf357f212f9cbd65bc01599670ed6b9d13f56` from candidate run `41150745596`, the toolchain image is pinned to `ghcr.io/btbn/ffmpeg-builds/win64-gpl@sha256:572cc7bc0974ebe2e5fd5f82c49e68c07942c6858098fd04f8daa23e3dc4dd2c`. The MinGW source revision for this image is `7213d719fe344553aa24fef7cc7dedee4940d594`, not `57b595039040eaa15bece85b7cc71d952281b269`. The candidate review recorded that all 349 headers differing between those revisions match `7213d719` in the image. The complete `7213d719` source archive is now pinned in `../sources.lock.json`; the three notice texts retain the same SHA-256 values at that revision. The older `57b595` note below describes a different recovered image/cache and must not be used as the source identity for this DLL.

Scoped Git attributes preserve these upstream files' bytes and original whitespace, including trailing spaces and the exception text's final blank line. Do not normalize their line endings or apply whitespace cleanup: the locked SHA-256 checks, rather than repository prose formatting, validate these original legal texts.

These notice files are also included with the toolchain source in the standalone prerelease [libmpv-6a6ac973-r2](https://github.com/Excentry/Ryotune-Omni/releases/tag/libmpv-6a6ac973-r2); that asset supplies GCC 16.2.0 and the crosstool-NG source/patch tree at `b1a94f65c5187d99037a4e2f57aefbdf995a9677`. The GCC 16.2.0 release source SHA-512 is verified against the upstream `sha512.sum`. The private candidate evidence maps all 101 linked GCC-family members to one source path each and confirms that the 16 reviewed patches do not modify linked `.c`, `.cc` or `.S` files. This is a source-path mapping, not a byte reproduction: libstdc++ objects have no DWARF, patch 0004 changes headers that may be compilation inputs, and patches 0022/0026 affect configure inputs.

The recovered BtbN `10-mingw` cache for the earlier image contains commit `57b595039040eaa15bece85b7cc71d952281b269`; it is not the source revision for the selected `6a6ac973` DLL. For the selected candidate, all 349 headers that differ between `57b595` and `7213d719` match the latter in the pinned image. The private review maps all 63 linked MinGW members to one source path each, with no explicit Cephes, Moshier, Wine or LGPL marker in those selected source files. The map does not enumerate every consumed header, compile flag or generated file, and the archive-root Cephes FIXME remains unresolved.

GCC's runtime exception applies to files bearing the relevant grant and eligible compilation processes; it does not relicense mpv, FFmpeg, Rubber Band or other independent modules. Copying a separate GCC runtime DLL is not automatically covered by the same reasoning as target code combined with independent modules. This recipe intends to avoid that extra DLL dependency rather than silently bundle one.

The MinGW runtime notice contains an unresolved upstream Cephes paragraph and references Wine-derived LGPL headers. Do not treat its root ZPL notice or this notice bundle as a complete per-object clearance. No upstream contact or license clarification request is authorized by this review.
